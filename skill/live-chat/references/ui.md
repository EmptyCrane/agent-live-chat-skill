# 聊天界面规范

## 设计原则

借鉴成熟即时通讯产品的信息层级和消息节奏，不复制其品牌、图标或页面。把界面定位为只读多智能体直播：页面只请求状态，不发送消息、reset 或其他写操作。

不使用持续粒子、canvas、blur、filter或常驻动画。通过静态CSS渐变、气泡层次和轻量状态过渡建立氛围。

## 响应布局

- `360–520px`：全宽单栏。顶栏展示场景、连接状态、最多3个叠放头像和成员数；其下展示目标、轮次和阶段；点击头像栈打开包含会话详情与名册的只读抽屉。
- `521–819px`：保持单栏，放宽消息区域并以居中卡片承载聊天流。
- `>=820px`：最大宽度1080px，使用聊天主栏加约292px参与者侧栏；侧栏展示完整目标、交付物、完成条件、角色关注点及成员，高度不足时分别滚动；不再打开成员抽屉。
- 多会话服务在桌面侧栏和移动成员抽屉中显示只读会话选择器。切换历史只发送GET请求，并在URL中保存`session`参数；归档会话必须明确标记。
- 不依赖固定400×760视口，由页面适应宿主内置页签或普通浏览器的实际宽度。

## 消息与状态

- 页面支持`en`和`zh-CN`两套完整界面文案；`?lang=en`或`?lang=zh-CN`可显式覆盖，未指定时中文浏览器使用简体中文，其他浏览器使用英文。场景和聊天正文属于用户数据，不做自动翻译。

- 顶栏约60px，使用明亮蓝色渐变；标题、副标题均单行省略并提供完整tooltip。
- 头像36px，气泡圆角12–14px，正文15.5px、行高1.55，最大宽度随断点变化。
- 名称和时间置于气泡顶部；连续同人发言缩短间距并隐藏重复头像和meta。
- 系统轮次显示为居中半透明胶囊；实时轮次可播放一次短高光。
- typing 固定在消息区底部，使用三点节奏动画；超过两名时显示两人和总人数并轮播。
- 参与者名册是成员总数和顺序的权威来源；状态显示“等待发言”“已发言”或“正在输入”。连接旧服务且缺少名册时，才从消息和 typing 推导。
- session为idle或旧服务缺少session时隐藏会话区；活动状态显示目标摘要、`第x/y轮`、阶段和状态。
- running、paused、waiting_user、completed、stopped和partial_failure使用蓝、橙、紫、绿、灰、红区分，但始终同时显示文字，不能只依赖颜色。
- 浅色主题采用天空蓝、近白聊天面和海军蓝正文；深色主题采用深海蓝，不使用大面积炭灰。
- 主题按钮按“自动→浅色→深色”循环，默认按 `prefers-color-scheme` 自动选择，并以 `live-chat-theme` 写入 `localStorage`。存储失败只影响记忆，不影响页面。

## 渲染与性能

- 新消息只使用200ms左右的 `opacity + transform` 动画，历史批量加载不播放动画。
- 首批及增量消息使用 `DocumentFragment` 一次提交，并在批次结束后只滚动一次。
- scene、typing、成员集合未变化时不更新相应DOM。
- session签名未变化时不更新目标条与详情DOM。
- 保持单飞轮询：正常500ms，请求超时4秒，失败退避至最多5秒。
- instance、epoch、total或消息ID不一致时清理派生状态并从 `since=0` 重拉。
- 使用 `textContent` 或显式DOM节点处理所有动态文本，禁止动态 `innerHTML`。
- 主题按钮是纯本地观看设置；页面仍不向任何写入端点发送请求。
- session、暂停和结束状态均为只读；页面不提供派发、暂停、继续或停止按钮。
- 会话选择器只读取`/api/sessions`和带`session`参数的`/api/state`，不得改变服务端活动会话。
- 尊重 `prefers-reduced-motion`，将所有非必要动画和过渡缩短到近乎静态。

## 无障碍

- 连接状态和typing使用礼貌的live region。
- 成员触发按钮暴露展开状态；成员抽屉支持关闭按钮、背景点击和Escape。
- 主题按钮暴露当前模式与切换动作。
- 会话目标条使用语义化区域；所有状态均有可读文字，长目标提供完整tooltip。
- 关键文本保持足够对比度，键盘焦点必须清晰可见。
